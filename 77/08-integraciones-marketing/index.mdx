# 08 | Integraciones de Marketing, Analytics & Meta / Google Ads

> **Módulo 08:** Especificación técnica para la arquitectura escalable de analítica, pixelado y atribución publicitaria de **77 Studio** mediante **Meta Business Suite (Pixel + CAPI)**, **Google Ads / GTM / GA4** y el motor de captura de parámetros UTM.

---

## 08.1 Arquitectura de Event Bus y Atribución

La web utiliza un **Event Bus client-side** centralizado en `src/scripts/tracking.ts`. Las interacciones se envían primero a `window.dataLayer` y Google Tag Manager decide qué eventos remitir a GA4, Google Ads u otras plataformas.

```
  [Usuario interactúa con 77 Studio]
               │
               ▼
    [src/scripts/tracking.ts]
               │
               ▼
     [dataLayer del navegador]
               │
               ▼
  [GTM-M6NH5PGW → GA4 / Google Ads]
```

### Eventos disponibles

| Evento | Cuándo se dispara | Uso recomendado |
|---|---|---|
| `view_service` | Visita a Marketing, Web, IA o Productos Digitales | Interés por servicio |
| `click_whatsapp` | Clic en cualquier enlace de WhatsApp, incluido el widget flotante y Sofía | Conversión secundaria |
| `click_email` / `click_phone` | Clic en correo o teléfono | Contacto secundario |
| `contact_cta_click` | Clic interno hacia formulario o página de contacto | Microconversión |
| `outbound_click` | Salida a un dominio externo | Navegación externa |
| `form_start` | Primera interacción con el formulario comercial | Inicio de formulario |
| `form_submit` | Intento de envío del formulario comercial | Diagnóstico; no es conversión final |
| `generate_lead` | Solo después de una respuesta real de éxito del backend | Conversión principal |
| `chat_open` / `chat_message_submit` | Apertura y uso de Sofía AI | Interacción comercial |
| `scroll_depth` | Profundidad de 25%, 50%, 75% y 90% | Calidad de lectura |

## 08.2 Google Ads, Google Tag Manager (GTM) & GA4

### 1. Google Tag Manager Container
- **Contenedor:** `GTM-M6NH5PGW`.
- **Configuración:** `PUBLIC_GTM_ID`, con el mismo ID como respaldo seguro en `BaseLayout.astro`.
- El script principal se carga al inicio de `<head>` y el iframe `noscript` inmediatamente después de abrir `<body>`.
- **Destino GA4 existente:** `G-8DCJ7P4HBB`.
- **Destino Google Ads existente:** `AW-11397435689`.

### 2. Conversiones de Google Ads
- **Conversión principal:** `generate_lead`, únicamente cuando el backend confirme que recibió el formulario.
- **Conversión secundaria:** `click_whatsapp`.
- El widget flotante se distingue con `link_location: whatsapp_floating` y `interaction_variant: floating_button` o `tooltip_cta`.
- `form_submit` mide intención y errores del embudo, pero no debe importarse como conversión principal.
- Los `conversion_label` se obtienen desde las acciones reales de Google Ads; no se inventan ni se incluyen en el repositorio.

Para confirmar un lead real, la integración del formulario debe emitir:

```typescript
window.dispatchEvent(new CustomEvent('77:lead-success', {
  detail: {
    form_id: 'lead-contact-form',
    form_origin: 'contacto',
    selected_service: 'marketing'
  }
}));
```

## 08.3 UTM Engine & Privacidad

`src/scripts/tracking.ts` captura y conserva la atribución durante la sesión. También inyecta estos valores como campos ocultos en el formulario comercial para que el futuro backend pueda guardarlos junto al lead.

### Parámetros almacenados
- `utm_source` (ej. `facebook`, `google`, `linkedin`, `newsletter`)
- `utm_medium` (ej. `cpc`, `paid_social`, `organic`)
- `utm_campaign` (ej. `campana-q3-ia-automatizacion`)
- `utm_content` / `utm_term`
- `gclid`, `gbraid`, `wbraid` y `fbclid`

### Protección de datos

- No se envían a `dataLayer` nombres, empresas, correos, teléfonos ni mensajes escritos.
- Los enlaces se registran sin parámetros de consulta para no exponer el texto prellenado de WhatsApp.
- `generate_lead` solo acepta metadatos técnicos permitidos: formulario, página de origen y servicio seleccionado.

---

## 08.4 Estado de Meta Pixel y CAPI

La web no inyecta un segundo Meta Pixel directamente en el código. Si el contenedor existente tiene una etiqueta de Meta Pixel, debe administrarse desde GTM para evitar eventos duplicados. Meta CAPI server-side queda fuera de esta implementación hasta disponer de Pixel ID, token seguro, endpoint y estrategia de deduplicación.
